1. The math of a classical biorhythm

The typical “three-cycle” biorhythm model uses three sinusoidal (sine wave) components, each with a fixed period:

  • Physical cycle: 23 days

  • Emotional cycle: 28 days

  • Intellectual cycle: 33 days brianmac.co.uk+2Dummies+2

Let ttt = number of days elapsed since birth (or since a reference “zero” point). Then:

physical(t)=sin⁡ ⁣(2π t23)\text{physical}(t) = \sin\!\bigl(\tfrac{2\pi\,t}{23}\bigr)physical(t)=sin(232πt​) emotional(t)=sin⁡ ⁣(2π t28)\text{emotional}(t) = \sin\!\bigl(\tfrac{2\pi\,t}{28}\bigr)emotional(t)=sin(282πt​) intellectual(t)=sin⁡ ⁣(2π t33)\text{intellectual}(t) = \sin\!\bigl(\tfrac{2\pi\,t}{33}\bigr)intellectual(t)=sin(332πt​)

You can scale or offset as you like (for display, mapping to percent, etc.). Some sources express it as a “percentage” by multiplying by 100, etc. study.com+2livingston.org+2

If you want to include a “critical day” flag, that’s usually when the sine crosses zero (i.e. switching sign).

You might also consider generalizing (e.g. other cycles, combinations, offsets) if you want to get fancy.

One nuance: if you use “days since birth,” you have to compute that reliably from date of birth to today, accounting for leap years etc.

So in code you’d do something like:

c
// pseudocode
int days = days_between(dob, today);
double phys = sin(2 * PI * days / 23.0);
double emot = sin(2 * PI * days / 28.0);
double intel = sin(2 * PI * days / 33.0);
// map from –1..+1 to e.g. 0..100% or –100..+100

You could also compute for past / future days, plot a curve, etc.

So mathematically it is trivial and very manageable on an ESP32.

2. Feasibility and challenges on ESP32 / M5StickC Plus2

From a hardware / embedded-systems standpoint, this is quite feasible. Some points and considerations:

Pros / trivial parts:

  • The compute requirement is minimal (few sines, a division, etc.). ESP32 is plenty powerful.

  • You have an RTC (real-time clock) on the board, or at least you can maintain a time basis via NTP or internal clock. The M5StickC Plus2 has an onboard RTC. docs.m5stack.com

  • You have a small display (1.14" TFT) to plot / show values. docs.m5stack.com

  • You can input the user’s date of birth (via menu, buttons, or even connect to smartphone / web) and then compute real‐time.

  • You could animate the curves over time, scroll graph, allow zooming, show “today’s values,” etc.

Challenges / things to watch:

  • Timekeeping / drift: If the clock drifts, your computed “days since birth” could be off slightly. For a project like this, small drift is acceptable, but you may want periodic sync (e.g. via NTP over Wi-Fi) or calibration.

  • Date arithmetic: You’ll need a robust routine to convert calendar date (year, month, day) to a day count (e.g. days since epoch). That’s straightforward but must handle leap years, etc.

  • Graph plotting in limited screen space: If you try to show several cycles over many days, you’ll need to manage scaling, axis drawing, etc.

  • Memory and rendering performance: Drawing curves and refreshing might require buffer management; with a small device you want to optimize how much you redraw.

  • User interface for entering date of birth: If buttons are limited, UI design matters.

  • Adding features: e.g. show critical days, show forecasts, overlay multiple users, store history, etc. That’s all doable but adds complexity.

  • Validity / expectations: As noted, biorhythm is not scientifically validated, so manage how realistic you promote it. But as a gadget / art / toy, that doesn’t matter too much.

Overall, there’s no showstopper. It’s fully within the scope of what an ESP32-based device can do.

4. Suggested architecture for your project

Here’s a rough outline to help you plan:

  1. Time / date module

    • Maintain current date/time (via RTC or NTP synchronization).

    • Convert date of birth and current date to days_since_birth.

  2. Biorhythm computation module

    • Functions for each cycle: physical, emotional, intellectual.

    • Accepts t (days) and returns a double in [–1, +1].

    • Optional: compute in discrete steps over a range, for plotting.

  3. UI / display module

    • Layout: maybe show current day values, mini-graph of past/future days, critical days marked.

    • Graphing: buffer or direct plotting, with axis, grid.

    • Input: menu / buttons to set DOB, switch modes, scroll graph.

  4. Data persistence / storage

    • Save user’s birthdate in nonvolatile memory (EEPROM, SPIFFS, preferences).

    • (Optional) log historical data or record interesting dates.

  5. Optional extras

    • Alerts / notifications for “critical days.”

    • Combine more cycles (e.g. intuitive cycle, custom cycles).

    • Sync via Bluetooth / Wi-Fi to a phone or web interface so you can view or export.

    • Export graph image or data.

    • Multi-user support.

  6. Performance & resource management

    • Compute math only when needed (on date change or redraw) to save CPU.

    • Use partial redraws of display rather than full refresh when possible.

    • Limit memory buffers for graphing.

#pragma once
#include <Arduino.h>

struct BiorhythmValues {
    float physical;
    float emotional;
    float intellectual;
};

class Biorhythm {
public:
    Biorhythm(int birthYear, int birthMonth, int birthDay);

    void setBirthDate(int year, int month, int day);
    BiorhythmValues compute(DateTime now);  // pass RTC or system time

private:
    int _birthYear, _birthMonth, _birthDay;
    int daysSinceBirth(DateTime now);
    float cycleValue(int days, int period);
};

🧮 biorhythm.cpp

cpp
#include "biorhythm.h"
#include <math.h>
#include <RTClib.h>  // You can swap this if you use M5 RTC functions

Biorhythm::Biorhythm(int year, int month, int day)
: _birthYear(year), _birthMonth(month), _birthDay(day) {}

void Biorhythm::setBirthDate(int year, int month, int day) {
    _birthYear = year;
    _birthMonth = month;
    _birthDay = day;
}

float Biorhythm::cycleValue(int days, int period) {
    return sin(2.0 * PI * (float)days / (float)period);
}

int Biorhythm::daysSinceBirth(DateTime now) {
    DateTime birth(_birthYear, _birthMonth, _birthDay);
    TimeSpan diff = now - birth;
    return diff.days();
}

BiorhythmValues Biorhythm::compute(DateTime now) {
    int days = daysSinceBirth(now);
    BiorhythmValues vals;
    vals.physical = cycleValue(days, 23);
    vals.emotional = cycleValue(days, 28);
    vals.intellectual = cycleValue(days, 33);
    return vals;
}

🕓 time_utils.cpp

cpp
#include "time_utils.h"
#include <M5StickCPlus2.h>

RTC_TimeTypeDef TimeStruct;
RTC_DateTypeDef DateStruct;

void TimeUtils::begin() {
    M5.begin();
    M5.Rtc.begin();
}

DateTime TimeUtils::now() {
    M5.Rtc.GetTime(&TimeStruct);
    M5.Rtc.GetData(&DateStruct);
    return DateTime(DateStruct.Year, DateStruct.Month, DateStruct.Date,
                    TimeStruct.Hours, TimeStruct.Minutes, TimeStruct.Seconds);
}

🖥 main.cpp (minimal)

cpp
#include <M5StickCPlus2.h>
#include "biorhythm.h"
#include "time_utils.h"

Biorhythm bio(1990, 1, 1);  // Example birth date

void setup() {
    M5.begin();
    Serial.begin(115200);
    TimeUtils::begin();

    Serial.println("Biorhythm demo start");
}

void loop() {
    DateTime now = TimeUtils::now();
    BiorhythmValues vals = bio.compute(now);

    Serial.printf("Day %02d/%02d/%04d\n", now.day(), now.month(), now.year());
    Serial.printf("Physical: %.2f | Emotional: %.2f | Intellectual: %.2f\n",
                  vals.physical, vals.emotional, vals.intellectual);

    // Example: map to % for display later
    int physPct = (vals.physical + 1.0) * 50;
    int emotPct = (vals.emotional + 1.0) * 50;
    int intelPct = (vals.intellectual + 1.0) * 50;

    Serial.printf("P:%d%% E:%d%% I:%d%%\n\n", physPct, emotPct, intelPct);

    delay(2000);
}
